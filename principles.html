01

Meaning
comes first.

HTML is not a delivery envelope for components. It is a vocabulary for describing what a page means.

A heading is a heading before it is 96 pixels tall. A button is a button before it has a gradient. When the structure is honest, browsers, search engines, assistive technology, reader modes, print engines, and tools can all participate.

Design the document before decorating the viewport.
FRAGILE<div onclick="go()">Continue</div>
DURABLE<a href="next.html">Continue</a>
02

Native
before novel.

The browser ships with decades of interaction design hidden behind ordinary-looking elements.

Start with links, buttons, forms, disclosure widgets, popovers, anchors, and scrolling. These primitives understand keyboards, touch, focus, history, validation, and user preferences. Custom behavior should begin where their capabilities genuinely end.

Field note 02-A

If an element navigates, use a link. If it changes the current state, use a button. Styling can make either look however it needs to look.

03

Progressive
by nature.

A website does not need to appear identical everywhere to remain coherent everywhere.

Ship a strong baseline. Layer container queries, scroll timelines, anchor positioning, blend modes, and view transitions inside feature queries. Older browsers receive the document. Newer browsers receive the choreography.

@supports (animation-timeline: scroll()) {
  .progress { animation-timeline: scroll(); }
}

@media (prefers-reduced-motion: reduce) {
  * { animation: none; }
}
04

Complexity must
pay rent.

Every abstraction creates a maintenance obligation. Demand a visible return.

Measure complexity in requests, bytes, concepts, failure modes, and the number of specialists required to make a sentence appear. The question is not whether a tool is fashionable. The question is whether the person visiting the page can feel its value.

Before adding machinery, ask:What becomes possible for the visitor?
